Ти — senior full-stack розробник і UI/UX дизайнер. Створи вебплатформу для проєкту
«НеВата» — інструмент для критичного оцінювання інформації (виявлення
маніпуляцій і фейків). Мова інтерфейсу — українська. Продукт — інструмент розвитку
критичного мислення, а не «остаточний арбітр правди»: це має відчуватися в тоні
текстів.

# 1. ТЕХНІЧНИЙ СТЕК (обов'язково)
- Next.js 14+ (App Router) + TypeScript
- Tailwind CSS + shadcn/ui, іконки lucide-react
- Zod для валідації та типів
- Supabase (Postgres + Auth + Storage) — підключи ПІЗНІШЕ, але структуру коду
  і схему БД підготуй одразу
- Деплой: Vercel
- Усі запити до аналізу йдуть через Next.js Route Handler `/api/analyze`
  (сервер), ніколи напряму з клієнта. API-ключі лише в .env, зберігаються
  на сервері
- Шар абстракції `lib/analysis/`: інтерфейс `AnalysisProvider` з методом
  `analyze(input): Promise<AnalysisResult>`. Зараз реалізація — `MockProvider`
  (заглушка). Згодом додаватимуться `LLMProvider` (Claude/OpenAI/Gemini)
  без змін в UI та API-контракті
- Мобільна адаптивність (mobile-first), світла тема, доступність (a11y)

# 2. КОНТРАКТ ДАНИХ (Zod-схеми, зроби одразу)
AnalysisInput:
  { type: "text" | "url" | "image", content: string, userAge?: number }

AnalysisResult:
  {
    verdict: "fact" | "fake" | "unverified" | "insufficient_data",
    isManipulative: boolean,   // новина може бути правдивою, але маніпулятивною
    riskScore: number (0–100),
    riskLevel: "low" | "medium" | "high",
    summary: string,
    signs: [{ title, description, quote? }],   // виявлені ознаки маніпуляції
    sources: [{ title, url, note? }],
    insufficientDataReason?: string
  }

Типи й схеми мають бути в одному місці (`lib/schemas.ts`) і використовуватися
і на клієнті, і на сервері.

# 3. СТОРІНКИ ТА ФУНКЦІОНАЛ

## Етап 1 — РОБИТИ ЗАРАЗ (MVP, Must have)

### Сторінка `/` — візитка проєкту (landing)
Секції:
1. Hero: назва, слоган, короткий опис, головна кнопка «Перевірити інформацію»
   → `/check`
2. Проблема (інформаційний потік, складно розпізнати маніпуляції)
3. Як це працює (3–4 кроки: вставте текст/посилання → запустіть аналіз →
   отримайте оцінку ризику → перевірте джерела)
4. Що ви отримаєте: Факт чи хиба, Рівень ризику 0–100%, Пояснення, Джерела
   (картки з іконками)
5. Для кого (молодь і студенти, користувачі соцмереж, споживачі новин,
   всі, хто розвиває медіаграмотність)
6. Цінність: «інструмент для розвитку критичного мислення, а не остаточний
   арбітр правди»
7. Дорожня карта (MVP → акаунти й історія → зображення → Telegram-бот)
8. Footer: навігація, контакти/команда, посилання «Про проєкт»
Навігація в шапці: Головна, Перевірити, Про проєкт, (праворуч кнопка
«Увійти» — неактивна, з позначкою «Скоро»).

### Сторінка `/check` — головний функціонал (US-01…US-08)
- Відкривається БЕЗ реєстрації (US-01)
- Перемикач вкладок: «Текст» | «Посилання» | «Зображення» (остання —
  disabled з бейджем «Скоро», US-11)
- Вкладка «Текст» (US-02): велике textarea, лічильник символів, мін. довжина
  (напр. 100 символів), кнопка «Вставити з буфера», кнопка «Очистити»
- Вкладка «Посилання» (US-03): input для URL з валідацією (http/https),
  підказка-приклад
- Кнопка «Проаналізувати» (US-04): стани — disabled при невалідному
  вводі, loading зі скелетоном/спіннером, error
- ПОКИ ЩО: аналіз НЕ підключений. Кнопка викликає `/api/analyze`, який
  використовує `MockProvider` і повертає демонстраційні дані, у відповідності
  до контракту. У UI над результатом покажи помітний банер
  «Демо-режим: аналіз ще не підключено». Режим перемикається змінною
  `NEXT_PUBLIC_DEMO_MODE=true`
- Компонент результату (зроби повністю, щоб потім просто отримувати
  реальні дані):
  • Вердикт-бейдж: «Факт» / «Хиба» / «Не підтверджено» / «Недостатньо даних»
    + окремий прапорець «Містить ознаки маніпуляції» (бо правдива новина
    може бути маніпулятивною) (US-04)
  • Рівень ризику (US-05): шкала/gauge 0–100% + категорія
    (низький / середній / високий) з кольоровою індикацією
    (не лише колір — ще й текст/іконка)
  • Пояснення (US-06): коротке резюме + список виявлених ознак
    (акордеон/картки: назва, опис, цитата з тексту)
  • Джерела (US-07): список карток із посиланнями (target=_blank,
    rel=noopener), для самостійної перевірки
  • Стан «Недостатньо даних» (US-08): окремий екран/блок з поясненням, чому
    висновок неможливий, і порадами (додайте більше тексту, вставте
    повне посилання). Не показувати ризик/вердикт у цьому стані
  • Дисклеймер: «Результат — підказка для критичного мислення, а не
    остаточний вердикт»
  • Кнопки: «Нова перевірка», «Копіювати результат»

### Сторінка `/about` — Про проєкт
Місія, бачення, як рахується ризик (загальний опис), обмеження системи,
команда, контакти.

### Службові
- `/not-found`, `/error`, сторінка «Політика конфіденційності» (коротка
  заглушка: введені тексти надсилаються на сервер для аналізу)

### API
- `POST /api/analyze` — приймає AnalysisInput, валідує через Zod, викликає
  провайдер, повертає AnalysisResult. Додай: rate limiting (простий
  in-memory зараз, готовий до Upstash), ліміт довжини тексту, санітизацію
  вводу, коректні HTTP-коди та повідомлення про помилки українською

# 4. СХЕМА БД (Supabase/Postgres, підготуй SQL-міграцію)
- profiles (id → auth.users, age, role: 'user'|'admin', created_at)
- analyses (id, user_id nullable, input_type, input_content, result jsonb,
  provider, prompt_version_id, created_at)
- prompt_versions (id, name, content, criteria jsonb, is_active, created_by,
  created_at)
- test_cases (id, input, expected_verdict, expected_risk_range)
- test_runs (id, test_case_id, prompt_version_id, actual_result jsonb, passed,
  created_at)
- error_logs (id, analysis_id, error_type, details, status, created_at)
Увімкни Row Level Security: користувач бачить лише свої analyses,
адмін — все.

# 5. ДИЗАЙН
- Сучасний, спокійний, довірчий стиль (медіа/освіта), без «алармістських»
  кольорів на лендінгу
- Ризик: зелений / жовтий / червоний + іконки й текстові мітки

- Всі кольори/відступи через Tailwind-токени, щоб згодом легко застосувати
  брендбук
- Мікроанімації (fade/slide) помірно
